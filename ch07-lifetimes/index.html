生命週期：借用的時間限制

每個參考都有「有效多久」的期限；標註生命週期，就是告訴編譯器參考之間的時間關係。

上一章我們看到，編譯器保證參考不會比它指向的資料活得更久，並在 dangle 的錯誤訊息裡遇到了「missing lifetime specifier」。這一章就來拆解這個機制：生命週期（lifetime）。

ℹ️
本章素材來源

主要範例與編譯器輸出取自官方 The Rust Programming Language 的 Validating References with Lifetimes（官方範例編號沿用原書，如 Listing 10-16）。生命週期邊界一節取自簡體中文技術文（AtomGit 開源社區），屬非官方來源，範例我們未逐一編譯驗證，使用時請以官方文件為準。

生命週期是什麼

官方文件說，生命週期是另一種「泛型」：型別參數確保型別具備我們要的行為，生命週期則確保參考在我們需要的時間內都有效。Rust 中每個參考都有生命週期，也就是該參考有效的作用範圍。多數時候它是隱含並由編譯器推斷的，就像型別大多可以推斷一樣；只有當參考之間的生命週期關係可能有多種可能時，才需要我們標註。

官方文件也坦白說：標註生命週期不是多數語言有的概念，會感覺陌生。

目標：防止懸空參考

生命週期的主要目的就是避免懸空參考。下面的程式有外層與內層兩個作用域：

Listing 10-16：使用已離開作用域的值的參考（官方 Rust Book，無法編譯）
fn main() {
    let r;

    {
        let x = 5;
        r = &x;
    }

    println!("r: {r}");
}
編譯器輸出（官方 Rust Book）
$ cargo run
   Compiling chapter10 v0.1.0 (file:///projects/chapter10)
error[E0597]: `x` does not live long enough
 --> src/main.rs:6:13
  |
5 |         let x = 5;
  |             - binding `x` declared here
6 |         r = &x;
  |             ^^ borrowed value does not live long enough
7 |     }
  |     - `x` dropped here while still borrowed
8 |
9 |     println!("r: {r}");
  |                   - borrow later used here

For more information about this error, try `rustc --explain E0597`.
error: could not compile `chapter10` (bin "chapter10") due to 1 previous error

錯誤訊息說 x「does not live long enough」：x 在內層作用域結束時就被釋放，但 r 在外層還活著；因為 r 的範圍較大，所以說它「活得比較久」。順帶一提，官方文件在這裡加註：這類先宣告、後給值的寫法並不表示 Rust 有 null；如果在給值之前使用變數，編譯時一樣會報錯。

Borrow checker：比較範圍大小

編譯器內建 borrow checker，會比較各個範圍，判斷所有借用是否有效。官方用標註把 r 的生命週期記為 'a、x 的記為 'b：

Listing 10-17：標註 r 與 x 的生命週期（官方 Rust Book）
fn main() {
    let r;                // ---------+-- 'a
                          //          |
    {                     //          |
        let x = 5;        // -+-- 'b  |
        r = &x;           //  |       |
    }                     // -+       |
                          //          |
    println!("r: {r}");   //          |
}                         // ---------+

編譯期比較兩者：r 的生命週期是 'a，卻指向生命週期為 'b 的記憶體，而 'b 比 'a 短，所以被拒絕：被參考的對象，活得沒有參考本身久。把 x 的宣告移到外層，就沒有問題：

Listing 10-18：資料的生命週期比參考長，所以有效（官方 Rust Book）
fn main() {
    let x = 5;            // ----------+-- 'b
                          //           |
    let r = &x;           // --+-- 'a  |
                          //   |       |
    println!("r: {r}");   //   |       |
                          // --+       |
}                         // ----------+

函式裡的泛型生命週期：longest

現在寫一個回傳兩個字串切片中較長者的函式。不拿走所有權，所以參數用字串切片（參考）。直接寫會失敗：

Listing 10-20：還不能編譯的 longest（官方 Rust Book）
fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest(string1.as_str(), string2);
    println!("The longest string is {result}");
}

fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() { x } else { y }
}
編譯器輸出（官方 Rust Book）
$ cargo run

error[E0106]: missing lifetime specifier
 --> src/main.rs:9:33
  |
9 | fn longest(x: &str, y: &str) -> &str {
  |               ----     ----     ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value, but the signature does not say whether it is borrowed from `x` or `y`
help: consider introducing a named lifetime parameter
  |
9 | fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
  |           ++++     ++          ++          ++

For more information about this error, try `rustc --explain E0106`.
error: could not compile `chapter10` (bin "chapter10") due to 1 previous error

原因是編譯器無法判斷回傳的參考是借自 x 還是 y；事實上我們自己也不知道，因為 if 回傳 x、else 回傳 y。呼叫前我們也不知道實際傳入參考的生命週期，所以沒辦法像前面那樣直接比較範圍。因此需要泛型生命週期參數來描述它們的關係。

標註語法

官方文件強調：生命週期標註不會改變任何參考活多久，它只描述多個參考的生命週期之間的關係。名稱以單引號開頭，通常全小寫且很短，慣例第一個叫 'a，寫在 & 之後，用空格與型別隔開：

生命週期標註語法（官方 Rust Book）
&i32        // a reference
&'a i32     // a reference with an explicit lifetime
&'a mut i32 // a mutable reference with an explicit lifetime

單獨一個標註沒有意義，標註的作用在於告訴 Rust 多個參考的泛型生命週期如何相互關聯。

函式簽名中的標註

我們要表達的限制是：回傳的參考，在兩個參數都有效的期間內都有效。於是把 'a 加到每個參考上：

Listing 10-21：指定所有參考共用同一個生命週期 'a（官方 Rust Book）
fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest(string1.as_str(), string2);
    println!("The longest string is {result}");
}

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

這個簽名告訴 Rust：對某個生命週期 'a，兩個參數至少活得和 'a 一樣久，回傳值也至少活得和 'a 一樣久。實務上，回傳參考的生命週期，等於兩個引數中較短的那一個。要注意：我們不是在改變傳入值的生命週期，而是在指定 borrow checker 應該拒絕所有不符合這些限制的值。標註放在函式簽名而非函式本體，它是函式合約的一部分，就像簽名中的型別。

用不同生命週期的引數實驗。string1 活到外層結束，string2 只活到內層結束，而 result 也在內層使用，借用檢查通過：

Listing 10-22：不同生命週期的 String 參考（官方 Rust Book）
fn main() {
    let string1 = String::from("long string is long");

    {
        let string2 = String::from("xyz");
        let result = longest(string1.as_str(), string2.as_str());
        println!("The longest string is {result}");
    }
}

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

接著把 result 的宣告移到外層、println! 也放到內層結束之後，就無法編譯：

Listing 10-23：string2 離開作用域後使用 result（官方 Rust Book，無法編譯）
fn main() {
    let string1 = String::from("long string is long");
    let result;
    {
        let string2 = String::from("xyz");
        result = longest(string1.as_str(), string2.as_str());
    }
    println!("The longest string is {result}");
}

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
編譯器輸出（官方 Rust Book）

人眼看得出 string1 比較長，所以 result 其實指向 string1；但我們已經告訴 Rust「回傳值的生命週期是兩個引數中較短者」，編譯器就只能依簽名判斷，保守地拒絕。

關係決定怎麼標

標註的寫法取決於函式做什麼。如果 longest 永遠回傳第一個參數，y 就不需要標註，因為 y 的生命週期與 x 或回傳值無關：

只有 x 與回傳值有關係（官方 Rust Book）
fn main() {
    let string1 = String::from("abcd");
    let string2 = "efghijklmnopqrstuvwxyz";

    let result = longest(string1.as_str(), string2);
    println!("The longest string is {result}");
}

fn longest<'a>(x: &'a str, y: &str) -> &'a str {
    x
}

回傳參考時，回傳型別的生命週期必須對應到某個參數；否則它指向函式內建立的值，那就是懸空參考。下例即使替回傳型別加了 'a 也無法編譯：

回傳區域變數的參考（官方 Rust Book，無法編譯）
fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest(string1.as_str(), string2);
    println!("The longest string is {result}");
}

fn longest<'a>(x: &str, y: &str) -> &'a str {
    let result = String::from("really long string");
    result.as_str()
}
編譯器輸出（官方 Rust Book）
$ cargo run

error[E0515]: cannot return value referencing local variable `result`
  --> src/main.rs:11:5
   |
11 |     result.as_str()
   |     ------^^^^^^^^^
   |     |
   |     returns a value referencing data owned by the current function
   |     `result` is borrowed here

For more information about this error, try `rustc --explain E0515`.

官方文件的建議是：此時最佳解法是回傳擁有所有權的型別，讓呼叫端負責清理。

結構體中的生命週期

結構體也可以持有參考，但每個參考都要加上生命週期標註。宣告方式與泛型相同：在結構體名稱後的角括號內宣告，再於欄位中使用。這表示 ImportantExcerpt 的實例不能比它持有的參考活得更久。

Listing 10-24：持有參考的結構體（官方 Rust Book）
struct ImportantExcerpt<'a> {
    part: &'a str,
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let i = ImportantExcerpt {
        part: first_sentence,
    };
}

例子中 novel 在實例建立之前就存在，也直到實例離開作用域之後才離開，所以參考有效。

省略規則：為什麼多半不用寫

你可能已經發現：前幾章的 first_word 沒有任何標註也能編譯。

Listing 10-25：沒有標註也能編譯的 first_word（官方 Rust Book）
fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }

    &s[..]
}

fn main() {
    let my_string = String::from("hello world");

    // first_word works on slices of `String`s
    let word = first_word(&my_string[..]);

    let my_string_literal = "hello world";

    // first_word works on slices of string literals
    let word = first_word(&my_string_literal[..]);

    // Because string literals *are* string slices already,
    // this works too, without the slice syntax!
    let word = first_word(my_string_literal);
}

官方文件說明這是歷史因素：Rust 1.0 之前，這段程式其實無法編譯，每個參考都需要明確的生命週期。後來 Rust 團隊發現程式設計師在特定情況下反覆輸入相同的標註，這些情況可預測且遵循確定的模式，於是把這些模式寫進編譯器，讓它自己推斷。這些模式稱為生命週期省略規則（lifetime elision rules）。它們不是給程式設計師遵守的規則，而是編譯器會考慮的特定情況；推斷完仍有歧義時，編譯器不會亂猜，而是報錯要你加標註。

函式或方法參數上的生命週期稱為輸入生命週期，回傳值上的稱為輸出生命週期。三條規則如下，規則一用於輸入，規則二、三用於輸出；也適用於 fn 與 impl 區塊：

  1. 編譯器為每個參考參數各指派一個生命週期參數：一個參數得一個，兩個參數得兩個獨立的。
  2. 如果只有一個輸入生命週期，它會被指派給所有輸出生命週期。
  3. 如果有多個輸入生命週期，但其中之一是 &self 或 &mut self（也就是方法），則 self 的生命週期會指派給所有輸出生命週期。

讓我們當一次編譯器。first_word 套用規則一與規則二後，所有參考都有了生命週期：

省略規則推導過程（依官方 Rust Book 說明整理）
fn first_word(s: &str) -> &str {            // 原始簽名
fn first_word<'a>(s: &'a str) -> &str {     // 規則一之後
fn first_word<'a>(s: &'a str) -> &'a str {  // 規則二之後

相對地，longest 套用規則一得到兩個獨立生命週期；規則二不適用（輸入不只一個），規則三也不適用（它不是方法）。三條規則跑完，回傳型別的生命週期仍然未定，所以 Listing 10-20 會報錯。

方法中的生命週期

為帶生命週期的結構體實作方法時，語法與泛型型別參數相同。屬於結構體欄位的生命週期，必須在 impl 之後宣告，並在結構體名稱之後使用，因為它們是型別的一部分。官方範例中，level 只有 &self 且回傳 i32，不需要標註；而 announce_and_return_part 有兩個輸入生命週期，規則一給 &self 與 announcement 各自的生命週期，再因為規則三，回傳值取得 &self 的生命週期：

方法中的生命週期（官方 Rust Book）
struct ImportantExcerpt<'a> {
    part: &'a str,
}

impl<'a> ImportantExcerpt<'a> {
    fn level(&self) -> i32 {
        3
    }
}

impl<'a> ImportantExcerpt<'a> {
    fn announce_and_return_part(&self, announcement: &str) -> &str {
        println!("Attention please: {announcement}");
        self.part
    }
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let i = ImportantExcerpt {
        part: first_sentence,
    };
}

'static：活滿整個程式

一個特殊的生命週期是 'static，表示該參考可以存活於整個程式執行期間。所有字串常值都是 'static，因為文字直接存在執行檔裡，永遠可用。

字串常值的 'static（官方 Rust Book）
let s: &'static str = "I have a static lifetime.";
⚠️
不要為了消除錯誤就加 'static

官方文件提醒：錯誤訊息有時會建議使用 'static（上一章的 dangle 就是）。但先想想那個參考是否真的、也真的想要活滿整個程式。多數情況下，這類建議源自試圖建立懸空參考或生命週期不匹配，正確做法是修正那個問題，而不是加 'static。

泛型、trait bound 與生命週期同場出現

生命週期也是泛型，所以生命週期參數與型別參數放在同一個角括號清單裡：

同時使用生命週期、泛型與 trait bound（官方 Rust Book）
fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest_with_an_announcement(
        string1.as_str(),
        string2,
        "Today is someone's birthday!",
    );
    println!("The longest string is {result}");
}

use std::fmt::Display;

fn longest_with_an_announcement<'a, T>(
    x: &'a str,
    y: &'a str,
    ann: T,
) -> &'a str
where
    T: Display,
{
    println!("Announcement! {ann}");
    if x.len() > y.len() { x } else { y }
}

延伸：生命週期邊界（非官方來源簡介）

一篇簡體中文技術文把「生命週期邊界」定位為編譯器與程式設計師之間的契約，並列出三種主要形式；這裡只做語法簡介，細節與範例的正確性以官方 Rust Reference 為準（官方 Rust Book 在本章結尾也建議進階情境參考 Rust Reference）。

三種生命週期邊界形式（簡體中文技術文，註解已轉繁體，未經編譯驗證）
// 1. 最基礎的生命週期邊界
T: 'a                    // 型別 T 中的所有引用都必須比 'a 活得長

// 2. 生命週期本身的邊界
'b: 'a                   // 生命週期 'b 比 'a 活得至少一樣長

// 3. 在 trait bound 中
fn generic<T: 'static>() // T 中不能有任何非 'static 引用

另外，該文提到還有 for<'a> 這種「對任意 'a 都成立」的高階 trait bound；多數情況下邊界可被編譯器推斷。這些屬於進階主題，素材只提到名稱與一句話說明，本書不展開。

💡
本章重點回顧

生命週期標註描述「參考之間的時間關係」，不改變任何值實際活多久；它寫在簽名上，是函式合約。編譯器靠 borrow checker 比較範圍，並用三條省略規則省下大部分標註；真的歧義時才需要你寫 'a。檢查全在編譯期，執行期零成本。
