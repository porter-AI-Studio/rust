第 5 章 · Part 2：所有權：Rust 的核心

所有權：堆疊、堆積與三條規則

不靠垃圾回收、也不用手動 free：Rust 讓編譯器在編譯期替你管記憶體。

前四章我們看過 Rust 的定位、工具鏈與基本語法。從這一章開始進入全書最核心的部分：所有權（ownership）。多數初學者在 Rust 卡關，都卡在這裡；但只要把它的設計理由搞懂，後面的借用、生命週期、智慧指標都會順很多。

ℹ️
本章範例來源

程式碼與編譯器輸出取自官方 The Rust Programming Language 的 What is Ownership? 一章（doc.rust-lang.org/book/ch04-01-what-is-ownership.html），註解保留原文英文。

三種管理記憶體的方式

官方文件把所有權定義為「一組規範 Rust 程式如何管理記憶體的規則」。所有程式在執行時都得處理記憶體的使用，常見做法有三種：

做法誰負責回收記憶體代表
垃圾回收（GC）執行時期定期掃描不再使用的記憶體有 GC 的語言
手動配置與釋放程式設計師自己呼叫 allocate 與 free多數沒有 GC 的語言
所有權系統編譯器依規則檢查，違反就不給編譯Rust

官方文件強調：所有權的各項機制都不會拖慢程式的執行速度，因為檢查全部發生在編譯期。代價是你得先學會這套規則。

先弄清楚堆疊與堆積

在 Rust 這類系統程式語言裡，值放在堆疊（stack）還是堆積（heap），會直接影響語言的行為。官方文件的說明可以整理成下表：

堆疊（stack）堆積（heap）
存放順序後進先出（LIFO），像一疊盤子較無組織，向配置器要一塊夠大的空間
資料大小編譯期就必須已知且固定編譯期未知或可能變動
存放方式push 與 pop配置器找空位、標記為使用中，回傳指標
速度較快，位置永遠在頂端較慢，要先找空位並記帳，存取還得跟隨指標

指標本身大小固定，所以可以放在堆疊上；真要讀資料時才順著指標走到堆積。函式被呼叫時，傳入的值（可能包含指向堆積的指標）與區域變數會 push 到堆疊，函式結束就 pop 掉。

官方文件指出：追蹤哪段程式碼在使用堆積上的哪些資料、減少重複資料、以及清掉不再使用的資料避免空間耗盡，這些問題正是所有權要解決的。換句話說，所有權的主要目的就是管理堆積資料。

所有權的三條規則

  • Rust 中的每個值都有一個擁有者（owner）。
  • 同一時間只能有一個擁有者。
  • 擁有者離開作用域（scope）時，值就會被丟棄（drop）。

先用最簡單的字串常值看作用域：變數從宣告那一刻起有效，到所在作用域結束為止。

Listing 4-1：變數與其有效範圍（官方 Rust Book）
fn main() {
    {                      // s is not valid here, since it's not yet declared
        let s = "hello";   // s is valid from this point forward

        // do stuff with s
    }                      // this scope is now over, and s is no longer valid
}

String：放在堆積上的字串

字串常值的內容在編譯期就已知，直接寫死在執行檔裡，所以又快又有效率，但也因此不可變。需要接收使用者輸入、或內容會增長的文字，就要用 String，它的內容配置在堆積上。String::from 會向配置器要記憶體，這部分各語言大同小異；不同的是「用完怎麼還」。

沒有 GC 的語言，通常要自己判斷何時不再使用並呼叫釋放函式；官方文件列出三種常見錯誤：忘了釋放會浪費記憶體、太早釋放會讓變數失效、釋放兩次也是 bug。你需要的是剛好一次 allocate 配一次 free。

Rust 的做法是：擁有者離開作用域時自動歸還。Rust 會在右大括號處自動呼叫特殊函式 drop，String 的作者就把釋放記憶體的程式碼放在那裡。

String 版本的作用域（官方 Rust Book）
fn main() {
    {
        let s = String::from("hello"); // s is valid from this point forward

        // do stuff with s
    }                                  // this scope is now over, and s is no
                                       // longer valid
}
String 可以修改，字串常值不行（官方 Rust Book）
fn main() {
    let mut s = String::from("hello");

    s.push_str(", world!"); // push_str() appends a literal to a String

    println!("{s}");
}
ℹ️
RAII

官方文件提到，C++ 把這種「在物件生命週期結束時釋放資源」的模式稱為 Resource Acquisition Is Initialization（RAII）；用過 RAII 的人，對 Rust 的 drop 不會陌生。

移動（move）：賦值就是過戶

整數的賦值很直覺：let y = x; 之後兩者都是 5，因為兩個 5 都只是 push 到堆疊的小值。但把同樣的寫法換成 String，行為就不同了。

一個 String 由三個部分組成，存在堆疊上：指向堆積內容的指標、長度（length）與容量（capacity）。let s2 = s1; 複製的就是這三個欄位，並沒有複製堆積上的資料。這帶來一個問題：s1 與 s2 離開作用域時都會嘗試釋放同一塊記憶體，這叫雙重釋放（double free），是會導致記憶體損毀、甚至安全漏洞的 bug。

Rust 的解法是：let s2 = s1; 之後，直接把 s1 視為失效。離開作用域時，只有 s2 會釋放記憶體。官方文件稱這個動作為「移動」，而不叫淺層複製，就是因為第一個變數同時被作廢。

嘗試在移動之後使用 s1（官方 Rust Book，無法編譯）
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;

    println!("{s1}, world!");
}
編譯器輸出（官方 Rust Book）
$ cargo run

  |              -- value moved here

error: could not compile `ownership` (bin "ownership") due to 1 previous error

錯誤訊息很值得讀：它指出 s1 的型別是 String、沒有實作 Copy trait，所以賦值時發生了移動，並建議改用 s1.clone()。這個設計也隱含一個保證：Rust 不會自動替你做「深層」複製，所以任何自動發生的複製，執行成本都不會太高。

與移動相對的另一種情形是重新賦值：對既有變數賦予全新的值時，Rust 會立刻對舊值呼叫 drop 並釋放記憶體。

重新賦值會立刻 drop 舊值（官方 Rust Book）
fn main() {
    let mut s = String::from("hello");
    s = String::from("ahoy");

    println!("{s}, world!");
}

clone 與 Copy

如果你真的想連堆積資料一起深層複製，要明確呼叫 clone。官方文件的說法是：看到 clone，就知道這裡正在執行可能很昂貴的程式碼，這是一個提醒你「這裡不一樣」的視覺訊號。

clone：明確的深層複製（官方 Rust Book）
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();

    println!("s1 = {s1}, s2 = {s2}");
}

那為什麼整數不用 clone、賦值後原變數還能用？因為大小在編譯期已知的型別整個放在堆疊上，複製很快，淺層與深層複製沒有差別，所以沒有理由讓原變數失效。這類型別會標註 Copy trait：賦值後不會移動，而是直接複製。

整數實作 Copy，賦值後 x 仍然有效（官方 Rust Book）
fn main() {
    let x = 5;
    let y = x;

    println!("x = {x}, y = {y}");
}

官方文件列出實作 Copy 的常見型別：所有整數型別（如 u32）、布林 bool、所有浮點數型別（如 f64）、字元 char，以及「成員全都實作 Copy 的 tuple」，例如 (i32, i32) 可以，(i32, String) 不行。另外，如果型別本身或其任一部分實作了 Drop，就不能再標註 Copy，否則編譯時會報錯。

函式也會移動所有權

把值傳給函式，行為與賦值相同：不是移動就是複製。傳入 String 會移動，傳入 i32 因為實作了 Copy 而不會。

Listing 4-3：函式與所有權、作用域（官方 Rust Book）
fn main() {
    let s = String::from("hello");  // s comes into scope

    takes_ownership(s);             // s's value moves into the function...
                                    // ... and so is no longer valid here

    let x = 5;                      // x comes into scope

    makes_copy(x);                  // Because i32 implements the Copy trait,
                                    // x does NOT move into the function,
                                    // so it's okay to use x afterward.

} // Here, x goes out of scope, then s. However, because s's value was moved,
  // nothing special happens.

fn takes_ownership(some_string: String) { // some_string comes into scope
    println!("{some_string}");
} // Here, some_string goes out of scope and `drop` is called. The backing
  // memory is freed.

fn makes_copy(some_integer: i32) { // some_integer comes into scope
    println!("{some_integer}");
} // Here, some_integer goes out of scope. Nothing special happens.

回傳值同樣可以轉移所有權。函式把區域變數當作回傳值交出去，所有權就「搬出」給呼叫端。

Listing 4-4：轉移回傳值的所有權（官方 Rust Book）
fn main() {
    let s1 = gives_ownership();        // gives_ownership moves its return
                                       // value into s1

    let s2 = String::from("hello");    // s2 comes into scope

    let s3 = takes_and_gives_back(s2); // s2 is moved into
                                       // takes_and_gives_back, which also
                                       // moves its return value into s3
} // Here, s3 goes out of scope and is dropped. s2 was moved, so nothing
  // happens. s1 goes out of scope and is dropped.

fn gives_ownership() -> String {       // gives_ownership will move its
                                       // return value into the function
                                       // that calls it

    let some_string = String::from("yours"); // some_string comes into scope

    some_string                        // some_string is returned and
                                       // moves out to the calling
                                       // function
}

// This function takes a String and returns a String.
fn takes_and_gives_back(a_string: String) -> String {
    // a_string comes into
    // scope

    a_string  // a_string is returned and moves out to the calling function
}

規律每次都一樣：賦值給另一個變數就是移動；含有堆積資料的變數離開作用域時，除非所有權已經移給別人，否則由 drop 清理。

可是每個函式都「收進來再還回去」實在太囉嗦。想要在函式裡用完還能繼續用，只能用 tuple 把參數連同結果一起回傳：

Listing 4-5：把參數的所有權還回去（官方 Rust Book）
fn main() {
    let s1 = String::from("hello");

    let (s2, len) = calculate_length(s1);

    println!("The length of '{s2}' is {len}.");
}

fn calculate_length(s: String) -> (String, usize) {
    let length = s.len(); // len() returns the length of a String

    (s, length)
}

官方文件的評語是：對一個應該很常見的需求來說，這樣做儀式感太重、工作太多。Rust 的解法是下一章的主角：參考（reference）。

💡
本章重點回顧

所有權的目標是管理堆積資料：一個值一個擁有者，擁有者離開作用域就 drop。賦值與傳參預設是「移動」，需要深層複製要明講 clone，只存在堆疊的簡單型別則因 Copy 自動複製。
