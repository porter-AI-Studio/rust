第 1 章 · Part 1：認識 Rust

Rust 是什麼：設計目標與適用場景

先看清楚 Rust 想解決什麼問題、靠什麼辦到，再決定要不要往下學。

一句話定位

Rust 官方網站與 GitHub 主倉庫的標語完全相同：「A language empowering everyone to build reliable and efficient software」，也就是讓每個人都能打造可靠且高效的軟體。主倉庫（rust-lang/rust）本身收錄編譯器、標準函式庫與文件。這句話裡的「可靠」與「高效」，正好對應官方列出的三個賣點。

設計目標官方說法（摘要）靠什麼達成
效能（Performance）快速且省記憶體，沒有執行期（runtime）也沒有垃圾回收器，可用於效能關鍵的服務、嵌入式裝置，並容易與其他語言整合不依賴 GC 的記憶體管理
可靠性（Reliability）豐富的型別系統與所有權模型，保證記憶體安全與執行緒安全，在編譯期就消除許多類型的 bug編譯期檢查
生產力（Productivity）完整文件、訊息清楚的友善編譯器，以及一流工具：整合的套件管理與建置工具、多編輯器支援、自動格式化等工具鏈

以上三點出自官方網站（rust-lang.org）的介紹文字，屬於官方自述，不是第三方評測。主倉庫的 README 進一步點名了工具鏈的成員：套件管理與建置工具 Cargo、自動格式化工具 rustfmt、linter Clippy，以及編輯器支援 rust-analyzer。下一章會實際用到 Cargo。

Rust 怎麼管理記憶體：第三條路

一篇 iThome 鐵人賽的學習筆記（作者實測環境為 Rust 1.63.0）把常見語言的記憶體管理分成兩派：一派由開發者自己配置與釋放，例如 C、C++；另一派交給垃圾回收（GC），例如 C# 與 Golang。Rust 則走第三條路，用「所有權」機制管理，這也是官方說「沒有 GC」的原因。筆記引用文件，把所有權濃縮成三條規則：

  • Rust 中每個數值都有一個變數作為它的擁有者（owner）。
  • 同一時間只能有一個擁有者。
  • 當擁有者離開作用域時，數值就會被丟棄。

第一個範例展示第三條規則：s 與 y 的壽命都由大括號範圍決定，不需要手動釋放，也不需要等 GC 回收。

作用域決定壽命（取自 iThome〈[Rust] 記憶體管理〉）（1／2）
fn main() {
    let s = "hello"; // s 誕生
    println!("{}", s);
} // s 死亡
作用域決定壽命（取自 iThome〈[Rust] 記憶體管理〉）（2／2，另一個獨立範例，各自放進自己的 main.rs）
fn main() {
    let x = {
        let y = 6; // y誕生
        y + 1
    }; // y死亡
    println!("x is {}", x);
}

第二個範例是新手最先撞到的牆：字串賦值給另一個變數後，所有權就「搬移」（move）了，原本的變數不能再用。作者貼出的編譯器輸出如下，編譯器同時給出 clone 的解法。

move 之後再使用（取自同一篇筆記）
let s1 = String::from("hello");
let s2 = s1;
println!("s1 is {}, s2 is {}", s1, s2);
編譯器輸出（取自同一篇筆記，Rust 1.63.0）
Compiling basic v0.1.0 (D:\projects\rust_learning\basic)
error[E0382]: borrow of moved value: `s1`
 --> src\main.rs:4:36
  |
2 |     let s1 = String::from("hello");
  |         -- move occurs because `s1` has type `String`, which does not implement the `Copy` trait
3 |     let s2 = s1;
  |              -- value moved here
4 |     println!("s1 is {}, s2 is {}", s1, s2);
  |                                    ^^ value borrowed here after move
ℹ️
所有權留到第 5 章

本章只要記住：Rust 把「誰負責釋放記憶體」寫進型別規則，由編譯器檢查。堆疊、堆積、借用與生命週期的細節，分別在第 5 到第 7 章展開。

適用場景：官方主打的四個領域

官方網站說明，Rust 社群在 2018 年決定針對幾個特定領域改善開發體驗（見官方 2018 roadmap），這些領域都有品質不錯的 crate 與入門指南。

領域官方描述（摘要）
命令列工具（Command Line）用健全的生態系快速做出 CLI 工具，並容易散布與維護
WebAssembly用 Rust 為 JavaScript 加速，一次一個模組，可發佈到 npm、搭配 webpack 打包
網路服務（Networking）效能可預期、資源佔用小、非常穩定，適合網路服務
嵌入式（Embedded）低資源裝置、需要底層控制又不想放棄高階便利時的選擇

官網另外聲稱全球有數百家公司在正式環境使用 Rust，從新創到大企業、從嵌入式到可擴充的網路服務都有。這是官方自述，沒有附公司名單，本章不引用具體數字。至於與 C++、Zig 的詳細比較，本章素材沒有提供，不在此展開；與 Go 的對照見第 4 章，Linux 核心與嵌入式見第 16 章。

版本與 edition：Rust 1.85 與 Rust 2024

Rust 官方部落格公告，Rust 1.85.0 於 2025 年 2 月 20 日發布，同時讓 2024 edition 進入穩定版。公告稱這是「目前發布過最大的 edition」。edition 是讓語言做出「可能破壞相容性」的改變，但改由專案自己選擇是否啟用的機制，所以舊專案不會被迫改程式。已用 rustup 安裝的人，用下面的指令就能升級。

升級到最新穩定版（取自 Rust 1.85.0 公告）
$ rustup update stable

2024 edition 的變更分成語言、標準函式庫、Cargo、Rustdoc、Rustfmt 幾類。語言面包含 unsafe extern 區塊、unsafe 屬性、禁止參考 static mut、if let 與區塊尾端運算式暫時值作用域的調整等；Cargo 面則讓依賴解析器會考慮 rust-version 欄位。公告說，許多情況下可用 cargo fix 自動遷移，且自動修正刻意保守，只保留原本語意，不代表建議的寫法。

同一版穩定的還有 async closure（async || {}），呼叫時回傳 future，並在標準函式庫 prelude 加入 AsyncFn、AsyncFnMut、AsyncFnOnce 三個 trait。下面是公告中的範例（節錄，未含 ready 的匯入），非同步會在第 13 章系統講解。

async closure 範例（節錄自 Rust 1.85.0 公告）
let mut vec: Vec<String> = vec![];

let closure = async || {
    vec.push(ready(String::from("")).await);
};
⚠️
版本以素材為準

本書後續內容以素材所述的 Rust 1.85 與 2024 edition 為基準；第三方文章（如上面的 iThome 筆記）使用較舊的 1.63.0，錯誤訊息的格式可能與你本機略有不同，官方 Rust Book 也提醒輸出會隨版本改善。

官方學習資源地圖

官方的「Learn Rust」頁面把資源分成三種入門方式：被暱稱為「the book」的《The Rust Programming Language》，從第一原理導覽並帶你做幾個專案；Rust by Example，以範例為主、文字很少且附練習；以及 Rustlings，在你自己的環境用命令列練習。核心文件包含標準函式庫、Edition Guide、Cargo Book、rustdoc Book、rustc Book 與編譯器錯誤索引，都能用 rustup doc 離線開啟。進階與領域書籍則有 Command Line Book、Embedded Book、The Reference 與談 unsafe 的 The Rustonomicon。本書的範例與錯誤訊息，大量取材自 The Book。
