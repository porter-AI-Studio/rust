前言

前言

為什麼 Rust 的學習曲線這麼陡，卻還是值得跨過去，又該用什麼態度看待它？

這本書要解決什麼問題

Rust 最大的門檻通常不是語法，而是所有權、借用與生命週期這套模型：它要求你在編譯期就把「誰負責釋放記憶體」「誰能同時讀寫」想清楚。習慣垃圾回收（GC）或手動管理記憶體的人，第一次看到編譯器拒絕編譯，容易覺得被刁難；其實那些錯誤訊息，擋下的正是別的語言要到執行期才會碰到的問題。

這本書用繁體中文，把 Rust 的核心概念與現實取捨整理成一條讀得下去的路線：先建立所有權的心智模型，再進到型別系統與錯誤處理，接著是並行與非同步，最後看系統層案例、批評與重寫代價。目標不是替 Rust 背書，而是讓你讀完之後，能判斷在自己的專案裡該不該用、用在哪裡、要付出什麼成本。

素材從哪裡來

全書不是憑空撰寫，每一章都對照作者收集的素材筆記，而素材的性質差異很大，所以書裡會盡量標出「這句話是誰說的」。大致分為四種：

  • 官方 Rust Book 與官方文件：The Rust Programming Language、Rust 官方網站與部落格、Rustonomicon、Linux 核心文件等，是本書的主要依據。
  • 第三方教學與學習筆記：例如 iThome 鐵人賽文章、部落格與中文社群文章，內容有參考價值，但不一定對應最新版本，其中也有簡體中文與英文的原文。
  • 廠商或公司自述：例如 Discord、Cloudflare、Momento 的工程分享，是第一手說法，但屬於自述，不是第三方量測。
  • 批評與轉述文章：例如對 Rust 的批評、開發者的抱怨，以及整理 Rust 挑戰的文章，其中有的是二手轉述，有的原文已被撤回，書裡會明確標示。
ℹ️
全書的來源紀律

一、官方資料優先於第三方。二、數字一律標明來源，並分清楚是量測、自述還是轉述。三、素材之間說法矛盾時並陳，不擅自挑一邊。四、素材沒有提供的內容就直接寫「素材未提供」，不用推測補上。五、若為了補足缺口而上網查，只採用官方文件，並標出網址。

版本基準

本書以素材所述的 Rust 1.85 與 2024 edition 為基準（Rust 1.85.0 為 2025 年 2 月發布，第 1 章有說明）。不過部分第三方文章用的是較舊的版本，例如第 1 章引用的筆記使用 Rust 1.63.0，所以書中某些編譯器錯誤訊息的格式，可能跟你本機看到的略有不同。你自己的環境、依賴版本與 API，請以 Rust 官方文件為準，特別是 Tokio 與 axum 這類更新較快的 crate。

這本書適合誰

  • 已經有其他語言經驗的開發者，特別是用 TypeScript 或 Go 的後端與全端工程師，想系統性理解 Rust 為什麼這樣設計。
  • 需要評估是否導入 Rust 的技術主管或架構師，想看的是代價與案例，而不只是效能數字。
  • 對系統層、嵌入式或 Rust for Linux 有興趣，想先弄懂這個領域的現況與限制的人。

先備知識只有一個：寫過程式，懂變數、函式、型別與基本的資料結構。不需要先懂記憶體管理；第 5 章會從堆疊與堆積講起。第 8 章專門以 TypeScript 的觀念對照所有權，第 4 章則整理與 Go 的取捨，這兩章就是為這兩群讀者準備的。

建議的閱讀路線

  • 完全沒碰過 Rust：照順序讀。第 1 到第 3 章快速建立全貌與語法，第 4 章幫你決定要不要繼續。
  • 已會 Rust 基本語法：直接從第 5 章開始，所有權、借用與生命週期是後面所有章節的基礎。
  • TypeScript 開發者：第 5 章讀完後接第 8 章，把所有權放回你熟悉的語言觀念裡再看。
  • 要寫服務端程式：先讀第 5 到第 7 章與第 9 章，再進第 12 到第 14 章。
  • 要做技術選型：先看第 4 章與第 17 章，需要案例時再讀第 16 章。
💡
只能讀一部分？請先讀完 Part 2（第 5 到第 8 章）

所有權是 Rust 與多數語言最不同的地方，也是新手最常卡關的地方。這幾章讀通之後，後面的 trait、並行與非同步，你才看得懂設計動機，而不只是記語法。

關於書裡的範例程式碼

書裡的程式碼與編譯器輸出，原則上逐字取自素材（官方 Rust Book、官方文件與各篇文章），並在標籤註明出處；註解多半保留原文，沒有替你重新設計範例。少數地方是「依素材改寫」，例如把原文件中的說明譯成繁體中文、或整理成較精簡的版本，這些都有在程式碼標籤標示。

這些範例沒有在本書的流程裡逐一重新編譯。放進你的專案之前，請自己用對應版本的 Rust 編譯一次，特別是依賴第三方 crate 的範例，素材有時只給程式碼而沒給完整的 Cargo.toml，需要你自行補上。

素材不足的地方

有些主題素材本來就比較少，書中不會硬寫成長篇大論，這裡先說明：

  • 第 14 章（Tokio 與 axum）：偏短。優雅關閉、觀測性與效能調校、axum 的錯誤處理與中介軟體，素材沒有範例，書中只指向官方文件。
  • 第 15 章（慣用寫法與小型專案）：偏短。慣用模式主要取自社群整理的文件，並非官方；小型專案只有官方 Rust Book 第 12 章的開場說明，沒有逐步實作的程式碼。
  • 第 16 章（系統層）：嵌入式的 no_std、裝置驅動與交叉編譯細節，素材未提供；Pingora 的數字是 Cloudflare 自述。
  • 第 17 章（現實檢查）：編譯速度的實測與學習曲線的量化，素材沒有自己的量測數字，書中只引用來源裡有的說法。

另外，書中提到的第三方數字，例如 Discord、Cloudflare、Momento 的案例，請當作「某來源的說法」，並留意各案例的時代背景。
