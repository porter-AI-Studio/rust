第 2 章 · Part 1：認識 Rust

安裝與 Cargo：第一個專案

從零安裝到跑起第一個 Cargo 專案，順便看一眼你以後會用到的發布流程。

用 rustup 安裝

官方建議透過 rustup 安裝 Rust。它是管理 Rust 版本與相關工具的命令列工具，安裝時需要網路連線，預設會裝最新的穩定版編譯器。Rust Book 並保證：能編譯的範例在較新的穩定版仍能編譯，只是輸出訊息可能略有不同。

Linux 與 macOS

開啟終端機，輸入下面的指令。安裝成功時會出現「Rust is installed now. Great!」。你還需要一個連結器（linker），Rust 用它把編譯結果合成一個檔案；多數人已經有了，遇到連結器錯誤再安裝 C 編譯器即可。macOS 可執行 xcode-select --install，Linux 則依發行版安裝 GCC 或 Clang，例如 Ubuntu 的 build-essential 套件。

安裝 rustup（取自 Rust Book「Installation」）
$ curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh

Windows

到 rust-lang.org/tools/install 依指示安裝。過程中會提示安裝 Visual Studio，因為它提供連結器與編譯所需的原生函式庫。書中後續的指令在 cmd.exe 與 PowerShell 都能執行。

驗證、更新與反安裝

用 rustc --version 確認安裝成功，輸出格式是版本號、commit hash 與 commit 日期。若看不到，檢查 PATH：Windows CMD 用 echo %PATH%，PowerShell 用 echo $env:Path，Linux 與 macOS 用 echo $PATH。

驗證、更新、反安裝與離線文件（取自 Rust Book「Installation」）
$ rustc --version
rustc x.y.z (abcabcabc yyyy-mm-dd)

$ rustup update
$ rustup self uninstall
$ rustup doc

rustup doc 會在瀏覽器開啟安裝時一併附上的本機文件，不需要網路。遇到標準函式庫的型別或函式不確定用法時，查 API 文件最快。編輯器方面，書中沒有指定工具，幾乎任何文字編輯器都行，官網的 tools 頁列有支援 Rust 的編輯器與 IDE。

第一個 Cargo 專案

Cargo 是 Rust 的建置系統與套件管理工具：編譯你的程式、下載依賴（你的程式需要的函式庫）、也編譯這些依賴。官方安裝程式會一併裝好 Cargo，可用 cargo --version 確認。Rust Book 後續章節都假設你使用 Cargo，本書也是。

建立專案（取自 Rust Book「Hello, Cargo!」）
$ cargo new hello_cargo
$ cd hello_cargo

Cargo 會建立同名目錄，內含 Cargo.toml 與 src/main.rs，並初始化 Git 儲存庫和 .gitignore；若已在 Git 儲存庫內執行則不會重複建立，也可用 --vcs 旗標改用其他版本控制。Cargo.toml 使用 TOML 格式，[package] 區段記錄名稱、版本與 edition，[dependencies] 區段列出依賴；Rust 的程式碼套件稱為 crate。edition 的意義在上一章說明過，這裡的 2024 表示使用 Rust 2024 edition。

Cargo.toml（Rust Book Listing 1-2）
[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]
src/main.rs
fn main() {
    println!("Hello, world!");
}

Cargo 預期原始碼放在 src 目錄；專案根目錄留給 README、授權資訊、設定檔等與程式碼無關的東西。已有不用 Cargo 的專案，可把程式碼移進 src，再執行 cargo init 產生 Cargo.toml。

build、run、check 與 release

cargo build 在 target/debug/ 產生可執行檔（Windows 上是 .exe），第一次執行還會在根目錄建立 Cargo.lock，記錄依賴的精確版本，由 Cargo 管理，不需要手動修改。cargo run 則把編譯與執行合為一步；原始碼沒變時，Cargo 會直接執行，不重新編譯。

build 與 run（取自 Rust Book「Hello, Cargo!」）
$ cargo build
   Compiling hello_cargo v0.1.0 (file:///projects/hello_cargo)
    Finished dev [unoptimized + debuginfo] target(s) in 2.85 secs

$ ./target/debug/hello_cargo # or .\target\debug\hello_cargo.exe on Windows
Hello, world!

$ cargo run
    Finished dev [unoptimized + debuginfo] target(s) in 0.0 secs
     Running `target/debug/hello_cargo`
Hello, world!
ℹ️
輸出格式隨版本而異

上面是 Hello, Cargo! 一節的輸出，寫著 dev [unoptimized + debuginfo]；同一本書其他章節的輸出則寫成「dev profile」加上相同的括號內容（例如 Rust Book 的 Control Flow 一節的 cargo run 輸出）。這是官方文件不同時期的差異，不是你的環境壞了。

cargo check 只檢查程式能不能編譯，不產生可執行檔，因此通常比 cargo build 快很多，很多 Rustacean（Rust 社群的自稱）寫程式時會定期執行，準備好要執行時再 build。Cargo 的指令在各作業系統上都一樣，這是它相對於直接呼叫 rustc 的優點。

指令用途輸出位置
cargo new建立新專案同名目錄
cargo build建置（預設 debug 模式）target/debug
cargo run建置並執行target/debug
cargo check只檢查能否編譯，不產生執行檔無
cargo build --release開啟最佳化的發布建置target/release

發布建置用 cargo build --release：最佳化讓程式跑得更快，代價是編譯時間更長，這也是為什麼有兩種 profile——開發時要頻繁重編，所以用不最佳化的 debug；交付給使用者的版本才用 release。官方特別提醒：要量測執行時間，務必用 target/release 的執行檔。接手別人的專案時，慣例流程也很簡單：

取得並建置現有專案（取自 Rust Book）
$ git clone example.org/someproject
$ cd someproject
$ cargo build

依賴與離線準備

Rust Book 的部分範例會用到標準函式庫以外的套件，需要網路，或事先把依賴下載到快取。做法是建立一個暫時專案，用 cargo add 加入書中用到的 crate，之後所有 cargo 指令都可加 --offline 使用快取。官方給的版本是 rand@0.10.1 與 trpl@0.2.0，這是該書撰寫當下的版本，你實際使用時請以書中指示為準。

預先下載依賴（取自 Rust Book「Installation」）
$ cargo new get-dependencies
$ cd get-dependencies
$ cargo add rand@0.10.1 trpl@0.2.0

依賴通常配合 Serde 這類 crate 使用。Serde 官方說明它是高效且通用的序列化與反序列化框架，設計上不靠執行期反射，而是靠 trait 系統：資料結構實作 Serialize 與 Deserialize，或用 derive 屬性在編譯期自動產生實作。因此幾乎沒有反射的額外開銷。下面是官方範例；素材沒有提供對應的 Cargo.toml 設定，實際使用需要在專案加入 serde 與 serde_json 兩個依賴，並依 serde 官方文件啟用 derive 功能。

Serde 的 derive 範例（取自 Serde 官方 Overview）
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize, Debug)]
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let point = Point { x: 1, y: 2 };

    // Convert the Point to a JSON string.
    let serialized = serde_json::to_string(&point).unwrap();

    // Prints serialized = {"x":1,"y":2}
    println!("serialized = {}", serialized);

    // Convert the JSON string back to a Point.
    let deserialized: Point = serde_json::from_str(&serialized).unwrap();

    // Prints deserialized = Point { x: 1, y: 2 }
    println!("deserialized = {:?}", deserialized);
}

文件註解與發布到 crates.io

Rust 有專門的文件註解：三條斜線 /// 支援 Markdown，放在被說明的項目之前，cargo doc 會呼叫 rustdoc 產生 HTML，輸出在 target/doc，cargo doc --open 還會直接在瀏覽器打開。範例區塊還有額外好處：執行 cargo test 時，文件裡的程式碼也會被當成測試跑，避免範例和程式碼脫節。

文件註解（Rust Book Listing 14-1，my_crate::add_one）
/// Adds one to the number given.
///
/// # Examples
///
/// ```
/// let arg = 5;
/// let answer = my_crate::add_one(arg);
///
/// assert_eq!(6, answer);
/// ```
pub fn add_one(x: i32) -> i32 {
    x + 1
}

要把自己的 crate 發布到 crates.io，流程是：用 GitHub 帳號登入 crates.io、在帳號設定取得 API token，執行 cargo login 貼上；token 存在本機 ~/.cargo/credentials.toml，屬機密，外流就要撤銷重發。接著在 Cargo.toml 補齊 crate 名稱（先到先得）、description 與 license（用 SPDX 識別碼，Rust 社群常見的是 MIT OR Apache-2.0 雙授權），缺欄位時 cargo publish 會報錯。

準備發布的 Cargo.toml（取自 Rust Book）
[package]
name = "guessing_game"
version = "0.1.0"
edition = "2024"
description = "A fun game where you guess what number the computer has chosen."
license = "MIT OR Apache-2.0"

[dependencies]
發布與撤回（yank）（取自 Rust Book）
$ cargo publish
$ cargo yank --vers 1.0.1
$ cargo yank --vers 1.0.1 --undo
⚠️
發布是永久的

版本一旦上傳就不能覆寫，程式碼也只在特殊情況才能刪除；crates.io 的目標是當成永久封存，讓所有依賴它的專案都能持續建置。出錯的版本可用 cargo yank 阻止新專案依賴，但既有的 Cargo.lock 不受影響。
