第 10 章 · Part 3：型別系統與錯誤處理

Trait、泛型、閉包與迭代器

Rust 的抽象能力來自四件事：泛型、trait、閉包與迭代器。其中泛型靠編譯期的 monomorphization 達到零執行期成本；trait object 的動態分派不在本章素材範圍，所以本章不對所有 trait 用法下「零成本」的結論。

上一章我們一直在用 Result<T, E>、From trait 與 unwrap_or_else 裡的閉包，卻沒有解釋它們。本章補上這塊拼圖。對 TypeScript 開發者來說，可以先這樣對照：泛型像 <T>，trait 像 interface（Rust Book 也說 trait 類似其他語言的介面，但有些差異），閉包像箭頭函式，迭代器像 map/filter 鏈。不同之處在於 Rust 在編譯期就把這些抽象展開成具體程式碼。本章範例皆取自 Rust 官方文件 The Rust Programming Language（以下簡稱 Rust Book）。

泛型：同一份邏輯，多種型別

泛型讓函式、結構、列舉與方法不必綁定具體型別。官方範例先寫了找最大值的 largest_i32 與 largest_char 兩個幾乎相同的函式，再合併成一個泛型函式 largest<T>：

Rust Book Listing 10-5：泛型 largest
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let number_list = vec![34, 50, 25, 100, 65];

    let result = largest(&number_list);
    println!("The largest number is {result}");

    let char_list = vec!['y', 'm', 'a', 'q'];

    let result = largest(&char_list);
    println!("The largest char is {result}");
}

這份程式碼不能直接編譯，因為編譯器不知道任意型別 T 能不能比較大小。錯誤訊息直接告訴你要加上 PartialOrd 限制，這就是下一節的 trait bound：

Rust Book：編譯器的錯誤訊息（節錄）
error[E0369]: binary operation `>` cannot be applied to type `&T`
 --> src/main.rs:5:17
  |
5 |         if item > largest {
  |            ---- ^ ------- &T
  |            |
  |            &T
  |
help: consider restricting type parameter `T` with trait `PartialOrd`
  |
1 | fn largest<T: std::cmp::PartialOrd>(list: &[T]) -> &T {

泛型也能用在結構與方法。impl<T> Point<T> 表示對所有 T 實作方法，impl Point<f32> 則只對 f32 版本提供 distance_from_origin：

Rust Book Listing 10-9／10-10：對泛型與特定型別分別實作方法
struct Point<T> {
    x: T,
    y: T,
}

impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

impl Point<f32> {
    fn distance_from_origin(&self) -> f32 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}

fn main() {
    let p = Point { x: 5, y: 10 };

    println!("p.x = {}", p.x());
}

泛型沒有執行期成本

Rust Book 指出，使用泛型不會讓程式比使用具體型別更慢。原因是編譯器做 monomorphization：把泛型程式碼依實際用到的型別展開成具體版本。官方以 Option<T> 為例，編譯器看到 Some(5) 與 Some(5.0) 後，會展開成類似下面的定義（官方註明編譯器實際用的名稱不同，這裡僅為說明）：

Rust Book：monomorphization 的示意結果
enum Option_i32 {
    Some(i32),
    None,
}

enum Option_f64 {
    Some(f64),
    None,
}

fn main() {
    let integer = Option_i32::Some(5);
    let float = Option_f64::Some(5.0);
}

這與 TypeScript 的泛型不同：TypeScript 的型別參數編譯後會被抹除，Rust 則是為每個型別各產生一份程式碼，用較大的執行檔換取沒有額外的執行期分派成本。（素材未提供執行檔大小的實測數字。）

Trait：定義共同行為

trait 把一組方法簽章集合起來，定義「某種行為」。官方範例是一個媒體彙整函式庫：NewsArticle 與 SocialPost 都能產生摘要，所以定義 Summary trait，再分別 impl Summary for 型別：

Rust Book Listing 10-12／10-13：定義並實作 Summary trait
pub trait Summary {
    fn summarize(&self) -> String;
}

pub struct NewsArticle {
    pub headline: String,
    pub location: String,
    pub author: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}, by {} ({})", self.headline, self.author, self.location)
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize(&self) -> String {
        format!("{}: {}", self.username, self.content)
    }
}

要注意孤兒規則（官方文件用語為「只能在 trait 或型別至少有一個屬於本地時實作」）：你可以對自己的型別實作標準函式庫的 trait，也可以對標準函式庫型別實作自己的 trait，但不能在自己的 crate 裡替 Vec<T> 實作 Display，因為兩者都不屬於你。

預設實作

trait 的方法可以有預設實作，而且預設實作能呼叫同一個 trait 中沒有預設實作的方法。因此實作者只需要補上必要的一小部分。下面的 SocialPost 只實作 summarize_author，就能直接使用 summarize，官方輸出為 1 new post: (Read more from @horse_ebooks...)。Rust Book 另外提醒，覆寫某個方法時，無法呼叫該方法的預設實作。

Rust Book：預設實作呼叫另一個方法
pub trait Summary {
    fn summarize_author(&self) -> String;

    fn summarize(&self) -> String {
        format!("(Read more from {}...)", self.summarize_author())
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize_author(&self) -> String {
        format!("@{}", self.username)
    }
}

trait 當參數與 trait bound

函式可以用 impl Trait 接受任何實作了該 trait 的型別，它其實是語法糖，完整寫法是 trait bound。兩個參數要求同型別時必須用 trait bound；要求同時實作多個 trait 用 +；限制太多、簽章變得雜亂時改用 where 子句。以下片段取自 Rust Book 不同小節的語法示範（原文為分開的片段，這裡合併顯示，不是單一可編譯程式）：

依素材改寫：trait bound、+ 語法與 where 子句（分段合併，非獨立程式，需自行補上 Display、Debug 的匯入）
pub fn notify<T: Summary>(item: &T) {
    println!("Breaking news! {}", item.summarize());
}

pub fn notify(item: &(impl Summary + Display)) {
}

fn some_function<T, U>(t: &T, u: &U) -> i32
where
    T: Display + Clone,
    U: Clone + Debug,
{
    unimplemented!()
}

impl Trait 也能用在回傳型別，回傳「某個實作了 Summary 的型別」而不必寫出具體型別，這對閉包與迭代器特別有用，因為它們的型別只有編譯器知道。但限制是只能回傳單一型別：同一個函式用 if 分支分別回傳 NewsArticle 或 SocialPost 是不允許的。Rust Book 說明要實現這種行為需要 trait object，素材中該章節在本書範圍之外，這裡不展開。

trait bound 還能讓方法「有條件地存在」。下面的 Pair<T> 永遠有 new，但只有 T 同時實作 Display 與 PartialOrd 時才有 cmp_display：

Rust Book Listing 10-15：依 trait bound 有條件實作方法
use std::fmt::Display;

struct Pair<T> {
    x: T,
    y: T,
}

impl<T> Pair<T> {
    fn new(x: T, y: T) -> Self {
        Self { x, y }
    }
}

impl<T: Display + PartialOrd> Pair<T> {
    fn cmp_display(&self) {
        if self.x >= self.y {
            println!("The largest member is x = {}", self.x);
        } else {
            println!("The largest member is y = {}", self.y);
        }
    }
}

閉包：能捕捉環境的匿名函式

閉包是可以存進變數或當參數傳遞的匿名函式，語法是 |參數| 運算式。官方用 T 恤公司送贈品的範例：使用者有偏好色就給偏好色，沒有的話呼叫閉包 || self.most_stocked() 挑庫存最多的顏色。閉包捕捉了 self，標準函式庫完全不需要知道 Inventory 的存在。

Rust Book Listing 13-1：unwrap_or_else 搭配閉包
#[derive(Debug, PartialEq, Copy, Clone)]
enum ShirtColor {
    Red,
    Blue,
}

struct Inventory {
    shirts: Vec<ShirtColor>,
}

impl Inventory {
    fn giveaway(&self, user_preference: Option<ShirtColor>) -> ShirtColor {
        user_preference.unwrap_or_else(|| self.most_stocked())
    }

    fn most_stocked(&self) -> ShirtColor {
        let mut num_red = 0;
        let mut num_blue = 0;

        for color in &self.shirts {
            match color {
                ShirtColor::Red => num_red += 1,
                ShirtColor::Blue => num_blue += 1,
            }
        }
        if num_red > num_blue {
            ShirtColor::Red
        } else {
            ShirtColor::Blue
        }
    }
}

fn main() {
    let store = Inventory {
        shirts: vec![ShirtColor::Blue, ShirtColor::Red, ShirtColor::Blue],
    };

    let user_pref1 = Some(ShirtColor::Red);
    let giveaway1 = store.giveaway(user_pref1);
    println!(
        "The user with preference {:?} gets {:?}",
        user_pref1, giveaway1
    );

    let user_pref2 = None;
    let giveaway2 = store.giveaway(user_pref2);
    println!(
        "The user with preference {:?} gets {:?}",
        user_pref2, giveaway2
    );
}
Rust Book：執行輸出
The user with preference Some(Red) gets Red
The user with preference None gets Blue

型別推斷與標註

閉包通常不需要標註參數與回傳型別，因為它的使用範圍很窄，編譯器能推斷。官方列出函式與閉包四種寫法的對照；需要注意的是，閉包的型別一旦被第一次呼叫推斷出來就固定了，之後用另一種型別呼叫會編譯失敗。

Rust Book：函式與閉包語法對照
fn  add_one_v1   (x: u32) -> u32 { x + 1 }
let add_one_v2 = |x: u32| -> u32 { x + 1 };
let add_one_v3 = |x|             { x + 1 };
let add_one_v4 = |x|               x + 1  ;

三種捕捉方式與 move

閉包依內容決定如何捕捉環境：不可變借用、可變借用、或取得所有權，正好對應函式參數的三種接收方式。下例的閉包因為呼叫 push 而捕捉可變參考，所以在定義與呼叫之間不能再使用 list。想強制取得所有權可以加 move，主要用途是把資料搬進新的執行緒，第 12 章談並行時會再用到：

Rust Book Listing 13-5：閉包可變借用
fn main() {
    let mut list = vec![1, 2, 3];
    println!("Before defining closure: {list:?}");

    let mut borrows_mutably = || list.push(7);

    borrows_mutably();
    println!("After calling closure: {list:?}");
}
Rust Book Listing 13-6：move 把所有權搬進執行緒
use std::thread;

fn main() {
    let list = vec![1, 2, 3];
    println!("Before defining closure: {list:?}");

    thread::spawn(move || println!("From thread: {list:?}"))
        .join()
        .unwrap();
}

Fn、FnMut、FnOnce

閉包會自動實作三個 trait 的其中一些，取決於它如何處理捕捉的值：

trait閉包的行為可呼叫次數
FnOnce可能把捕捉的值移出閉包本體；所有閉包都至少實作它一次
FnMut不移出捕捉的值，但可能修改它多次
Fn不移出也不修改捕捉的值，或什麼都沒捕捉多次

標準函式庫用 trait bound 限制能傳入哪種閉包。unwrap_or_else 只會呼叫一次，所以要求 FnOnce：

Rust Book：unwrap_or_else 的定義
impl<T> Option<T> {
    pub fn unwrap_or_else<F>(self, f: F) -> T
    where
        F: FnOnce() -> T
    {
        match self {
            Some(x) => x,
            None => f(),
        }
    }
}

相對地，sort_by_key 對每個元素都呼叫一次閉包，所以要求 FnMut。若閉包把捕捉的值移出（官方範例是把 value push 進外部的 vector），就只實作 FnOnce，無法傳給 sort_by_key。

迭代器：惰性的序列處理

Rust 的迭代器是 lazy 的：建立迭代器本身不做任何事，直到呼叫消耗它的方法才會執行。所有迭代器都實作標準函式庫的 Iterator trait，只需要定義 next 方法，每次回傳 Some(元素)，結束時回傳 None：

Rust Book：Iterator trait 的定義
pub trait Iterator {
    type Item;

    fn next(&mut self) -> Option<Self::Item>;

    // methods with default implementations elided
}

type Item 是關聯型別，素材說明之後的章節會深入介紹。呼叫 next 會改變迭代器內部狀態，所以變數要宣告成 mut；iter() 產生的是不可變參考的迭代器，想取得所有權要用 into_iter。

  • 消耗型方法（consuming adapters）：會呼叫 next 把迭代器用完，例如 sum；呼叫後原迭代器不能再用。
  • 迭代器轉接器（iterator adapters）：例如 map、filter，不消耗迭代器，而是產生另一個迭代器；因為是 lazy，必須再接一個消耗型方法（如 collect）才會真的執行，否則編譯器會警告「iterators are lazy and do nothing unless consumed」。
Rust Book Listing 13-15：map 搭配 collect
fn main() {
    let v1: Vec<i32> = vec![1, 2, 3];

    let v2: Vec<_> = v1.iter().map(|x| x + 1).collect();

    assert_eq!(v2, vec![2, 3, 4]);
}

閉包與迭代器結合時，閉包常會捕捉環境。下例的 filter 閉包捕捉了參數 shoe_size，只留下尺寸相符的鞋子：

Rust Book Listing 13-16：filter 閉包捕捉環境（略去測試）
#[derive(PartialEq, Debug)]
struct Shoe {
    size: u32,
    style: String,
}

fn shoes_in_size(shoes: Vec<Shoe>, shoe_size: u32) -> Vec<Shoe> {
    shoes.into_iter().filter(|s| s.size == shoe_size).collect()
}
ℹ️
與 TypeScript 的對照

JavaScript 的 arr.map(...).filter(...) 每一步都會產生新的陣列；Rust 的轉接器鏈是惰性的，最後一次消耗才逐元素走完整條管線。素材沒有提供兩者的效能比較數據，這裡只談設計差異。

小結

  • 泛型靠 monomorphization 達到零執行期成本；trait bound 是對泛型型別的行為要求。
  • trait 可以有預設實作，也可用 impl Trait 當參數或回傳型別（回傳時限單一型別）。
  • 閉包依內容自動捕捉環境，並依處理方式實作 Fn／FnMut／FnOnce。
  • 迭代器是惰性的，轉接器要搭配消耗型方法才會執行。
